Automatic Backup

Save completed tournaments automatically — locally and to a remote instance.

Overview

NewTon is offline-first — everything is stored locally in your browser. This works brilliantly for running tournaments without an internet connection, but it means tournament data lives on one machine.

Automatic Backup bridges the gap:

  • Local backup — when a tournament is finalized, the complete tournament data is saved to the server as a JSON file. No button to click, no export to remember. It happens silently at the moment of completion.
  • Remote backup — optionally, the same data is uploaded to a second instance at the same time. Tournaments run locally, but results are available online immediately.
  • Immediately available — saved tournaments appear in Analytics for all users, on any device. The moment a tournament is finalized, everyone can see the results.

Use Case

Here is how our club uses it:

At the venue, we have a dedicated computer for the Tournament Manager. It comes out for each tournament, then goes back in the storage locker. Internet at the venue is spotty, so we rely on the offline functionality — the Tournament Manager runs without a connection.

At the end of a tournament, whatever internet connection we have is enough to upload the completed tournament to our online instance. This instance runs in Analytics Mode — a read-only view of all tournament data.

Once uploaded, anyone can open the online instance on their phone and access the full stats — cross-tournament leaderboard, player rankings, match history, achievements — all from their pocket.

Local Backup

When Automatically backup tournaments on completion is enabled, finalizing a tournament saves the complete tournament data as a JSON file to the server’s persistent storage (as configured in your Docker Compose volume mounts).

Saved tournaments appear in Shared Tournaments for all visitors on that instance. They can be imported to Recent Tournaments manually. Analytics picks them up automatically — every completed tournament becomes part of the cross-tournament statistics for everyone who visits the site.

Duplicate protection is built in — uploading a tournament that already exists on the server will not overwrite the existing copy.

Remote Backup

In addition to the local backup, tournaments can be uploaded to a second instance at the moment of completion. The venue computer saves locally and pushes to the online Analytics instance in one step.

The upload happens immediately. If there is no internet connection at that moment it does not succeed, but it is not forgotten: see when an upload fails.

The receiving instance needs NEWTON_API_ENABLED=true in its Docker configuration. To keep strangers from uploading to it, set NEWTON_API_KEY there and enter the same key on the venue computer. Members can still open Analytics without a login: only uploads, deletes and corrections need the key.

Setup

In Global Settings, scroll to Server Settings:

  1. Tick Automatically backup tournaments on completion. This enables the local backup.
  2. For remote backup, fill in the Remote Backup fields:
    • Remote server URL — the full URL of the receiving instance (e.g. https://my.other.instance)
    • API key — the NEWTON_API_KEY set on the remote instance (leave empty if it has none)
  3. Click Save Server Settings.

That’s it. The next time a tournament is finalized, it will be saved locally and uploaded to the remote instance automatically.

Analytics Mode

The remote instance is typically configured with NEWTON_MODE=analytics in Docker. In Analytics Mode:

  • The full Tournament Manager interface is hidden — visitors see only Analytics.
  • Data is read-only. No tournaments can be created or modified through the UI. Tournament JSON files can still be imported via Analytics.
  • All uploaded tournaments appear automatically in the cross-tournament statistics.
  • The leaderboard, player rankings, match history, and achievements are all available.
  • Works on mobile — designed to be checked from your phone.

See the Docker Quick Start for environment variable reference.

When an Upload Fails

A tournament that did not reach the remote server says so. Setup shows “Not uploaded to …” with the reason and an Upload now button, the bracket page shows a Not uploaded chip, and the tournament’s row in Setup’s list carries a Not uploaded tag, so anyone can find it later.

  • It is tried again by itself while the page is open: after 30 seconds, a minute, two minutes, then every five minutes, at once when the connection comes back, and when the page is opened with a failed upload waiting.
  • A refusal is not retried. A wrong API key, a host that is not allowed or a file that is too large waits for someone to fix it; the message says which. Upload now tries it at once and tells you what happened.
  • The tag and the notice go when the upload succeeds. Only the remote server is followed; the local server is this computer’s own.
  • A tournament that is not loaded is retried when it is loaded again; load the one with the tag and press Upload now.

Live View

Optional, and off by default. With Global Settings → Server → Live copy while it is played on, the venue computer sends a slim copy of the tournament to its server, and to the remote server, after every change: the players and their statistics, the matches with scores, lanes and what each one recorded. Nothing is sent before the bracket is drawn.

  • On the Analytics site, a “Live now” line appears at the top of Analytics while a tournament is being played, with Watch. It opens a list of what is being played (with the lane), what is up next and the latest results; Bracket and Leaderboard are one tap away. It is read-only and updates by itself.
  • The live copy is not part of Analytics. It is kept apart, and goes when the finished tournament has been backed up. Analytics takes the finished tournament in as usual. If the backup fails, the live copy stays and shows the finished state until the upload succeeds, or for three days at most.
  • Anyone who can open the server can read it, as with the finished tournament. Writing it needs the API key.
  • It needs a server with the API (Docker). Without one, the setting does nothing.

Manual Fallback

If an upload does not succeed and you cannot wait for the retry (or the refusal needs a fix first), you can also:

  1. Export the tournament as a JSON file from the Tournament Manager (Recent Tournaments → Export).
  2. Upload the JSON file to the Analytics instance manually (Analytics → Import).

Manually imported tournaments are also added to Shared Tournaments on the receiving instance, just like automatic uploads. The same duplicate protection applies.

The local backup still happens regardless of internet connectivity — only the remote upload is affected.

Requirements

  • Docker — automatic backup is a server-side feature. It requires the Docker installation.
  • NEWTON_API_ENABLED=true — the API must be enabled on both the sending and receiving instances.
  • Persistent storage — configure volume mounts in Docker Compose so saved tournaments survive container restarts.
  • NEWTON_API_KEY (optional) — recommended on the remote instance, so only your venue can upload to it while members read freely.
